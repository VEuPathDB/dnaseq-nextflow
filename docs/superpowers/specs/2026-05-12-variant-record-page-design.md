# Variant Record Page — Data Model & Pipeline Design

**Date:** 2026-05-12
**Scope:** Additional data to surface on the webapp variant record page (one page per CHR+LOC). Covers new `.dat` files, extensions to existing `.dat` files, pipeline changes, and page layout.

---

## Background

The `mergeExperiments` workflow currently produces three `.dat` files loaded into PostgreSQL:

| File | Granularity | Key content |
|---|---|---|
| `variationFeature.dat` | one row per CHR+LOC | ref/major/minor allele, strain counts, coding flag, transcript, codon, amino acid products, nonsynonymous/stop flags |
| `allele.dat` | one row per CHR+LOC+allele | strain count, allele count, avg coverage, avg percent |
| `product.dat` | one row per CHR+LOC+codon+transcript | codon, amino acid, CDS position, downstream-of-frameshift |

**Primary audience:** bench biologists (page display). Bioinformaticians are served by downloadable merged VCF.

---

## New Data Files

### `sample.dat` (new)

Generated from the nf-core samplesheet CSV at load time. Auto-assigns sequential integer IDs.

```
strain_id (int) | sample_name (text)
1               | LmjF_strain_A
2               | LmjF_strain_B
42              | LmjF_strain_C
```

- Generated early in the workflow, before `processSequenceVariations.jl`
- Downstream steps use `strain_id` integers when building `allele.dat`

---

### `snpeff.dat` (new)

One row per (location, seq_id, allele, transcript_id). Parsed from the SnpEff-annotated merged VCF `ANN` field.

```
location | seq_id  | allele | transcript_id     | snpeff_impact | snpeff_effect
3745     | LmjF.01 | G      | LmjF.01.0010:mRNA | MODERATE      | missense_variant
3745     | LmjF.01 | C      | LmjF.01.0010:mRNA | HIGH          | stop_gained
```

- Generated by a new post-SnpEff step (separate script from `processSequenceVariations.jl`)
- Follows the same per-transcript granularity as `product.dat`
- `snpeff_impact`: HIGH / MODERATE / LOW / MODIFIER
- `snpeff_effect`: SnpEff effect term (e.g., `missense_variant`, `stop_gained`, `frameshift_variant`, `synonymous_variant`)

## Extended Data Files

### `allele.dat` — add `strain_ids integer[]`

Add a PostgreSQL integer array column listing which strains carry each allele.

```
location | seq_id  | allele | distinct_strain_count | allele_count | avg_coverage | avg_percent | strain_ids
61       | LmjF.01 | C      | 1                     | 1            | 10.00        | 60.00       | {42}
61       | LmjF.01 | G      | 5                     | 5            | 88.09        | 68.00       | {1,7,12,33,88}
```

**Scale rationale:** ~9K samples × ~1.5B total per-strain alleles → storing per-strain rows directly is infeasible. The array column reduces storage to one row per (location+allele), with strain IDs as an integer array.

- GIN index on `strain_ids` for fast array overlap queries
- Per-strain coverage/frequency intentionally excluded from the page — available in the VCF download
- Array column supports future joins to sample metadata via `unnest()`:

```sql
SELECT a.allele, s.country, count(*) AS strain_count
FROM allele a
JOIN LATERAL unnest(a.strain_ids) AS sid ON true
JOIN sample s ON s.strain_id = sid
WHERE a.location = 3745 AND a.seq_id = 'LmjF.01'
GROUP BY a.allele, s.country;
```

## Pipeline Changes

Current workflow order:
```
mergeVCFs → processSequenceVariations.jl → addFeatureIds → SnpEff
```

New workflow order:
```
samplesheet → sample.dat (new step)
mergeVCFs → processSequenceVariations.jl (extended: populate strain_ids in allele.dat) → addFeatureIds → SnpEff → parse ANN → snpeff.dat (new step)
```

### Changes to `processSequenceVariations.jl`
- Accept `sample.dat` as input to map sample names → strain IDs
- When iterating VCF sample columns to compute allele counts, also collect `strain_id` per allele
- Write `strain_ids` array to `allele.dat`

### New: `sample.dat` generation step
- Reads samplesheet CSV
- Assigns sequential integer IDs
- Writes `sample.dat`
- Runs before `processSequenceVariations.jl`

### New: SnpEff ANN parsing step
- Runs after SnpEff annotates the merged VCF
- Parses `ANN` field: extracts allele, transcript_id, impact, effect
- Writes `snpeff.dat`
- Self-contained — separate script from `processSequenceVariations.jl`

### Explicitly out of scope
- VCF QUAL, strand bias (SAP), mapping quality (MQM) — VCF download only
- Per-strain coverage/allele frequency — VCF download only
- Strain geographic/clinical metadata — loaded separately; `strain_ids` array supports future joins without schema changes

## Variant Record Page Layout

One page per CHR+LOC. Optimized for bench biologists; bioinformaticians use the VCF download.

### Header
- Chromosome + position (e.g., `LmjF.01 : 3,745`)
- Reference allele + reference strain
- Coding / Non-coding badge
- Highest SnpEff impact across all alleles/transcripts (e.g., `HIGH` highlighted)

### Allele Summary
Sourced from `allele.dat`.

| Allele | # Strains | Avg Coverage | Avg Freq (%) |
|--------|-----------|--------------|--------------|
| C      | 3         | 45.2         | 72%          |
| G      | 2         | 88.1         | 68%          |

### Functional Annotation
Sourced from `product.dat` + `snpeff.dat`, grouped by transcript.

| Transcript | Allele | Codon | AA | Impact | Effect |
|---|---|---|---|---|---|
| LmjF.01.0010:mRNA | C | GAC | D | HIGH | stop_gained |
| LmjF.01.0010:mRNA | G | CAC | H | MODERATE | missense_variant |

### Strain Breakdown
Sourced from `allele.dat.strain_ids` joined to `sample.dat`.

```
Allele C → LmjF_strain_A
Allele G → LmjF_strain_B, LmjF_strain_C
```

### Download
Link to merged VCF slice for this location — per-sample GT/DP/AO fields for bioinformaticians.
